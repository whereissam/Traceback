12 張投影片的完整講解。每張都附：**要講什麼**、**為什麼這樣講**、**評審可能問什麼**。

## 先記住這三句

整場 pitch 就靠這三句撐起來，其他都是支撐材料：

1. **「你批准的是指令，不是 npm 幫套件跑的那段程式碼。」** —— 問題
2. **「同一個引擎，esbuild 放行、惡意套件阻擋。」** —— 證明
3. **「機器不會自己確認自己的假設。」** —— 差異化

如果只剩 30 秒，講這三句就好。

---

## 第 1 張 · 封面

> **Traceback — 給 AI coding agent 安裝 npm 套件用的證據式安全閘門**

### 講什麼

> 「Traceback 是一個安全閘門。當 AI coding agent 要幫你裝 npm 套件的時候，它先在隔離沙箱裡把這個套件的安裝腳本跑一遍，看它**實際上**做了什麼，然後才決定要不要讓它碰你的機器。
>
> 核心原則是：**不要相信套件說它會做什麼，去觀察它實際做了什麼。**」

### 為什麼這樣講

不要一開場就講技術架構。先給一句話讓評審知道這是什麼類別的東西——「安全閘門」四個字就定位完了。

---

## 第 2 張 · The gap（問題）

> **你的 agent 問你能不能跑 `npm install`。那不是你真正在批准的東西。**

### 講什麼

> 「現在的 AI coding agent 在執行指令前都會問你：
>
> `Cursor wants to run: npm install analytics-helper`
>
> 你按了同意。但 npm 不只是下載檔案——它會**自動執行套件作者寫的程式碼**：
>
> `{ "scripts": { "postinstall": "node postinstall.js" } }`
>
> 這段程式碼跟你自己寫的程式碼權限一樣大。它可以開新的 process、讀你的 `.env`、讀 `~/.ssh`、對外連線、改你的 `.github/workflows`。
>
> **這些都沒有出現在你剛剛批准的那個對話框裡。**
>
> 而且它可能藏在依賴的依賴裡——最上層的套件看起來完全正常。」

### 為什麼這樣講

這是整場最重要的一張。評審必須先相信「這是個真問題」，後面的技術才有意義。

**節奏建議**：講到「這些都沒有出現在你剛剛批准的對話框裡」時停一拍。這句是轉折點。

### 可能被問

**Q：npm 不是有 `--ignore-scripts` 嗎？**

> 有，但預設不開，而且開了很多套件會裝不起來（像 esbuild 就需要 postinstall 下載對應平台的 binary）。所以實務上大家都是開著 scripts 在裝。我們的做法不是關掉它，是**先在別的地方跑一遍看它想幹嘛**。

## 第 3 張 · How it works（流程）

> **安裝腳本在沙箱裡跑，不在你的機器上跑**

### 講什麼

指著五個步驟講：

> 「流程是五步：
>
> 1. **攔截** —— 先用 `--ignore-scripts` 下載，本機什麼都不執行
> 2. **引爆** —— 在隔離沙箱裡跑它的安裝腳本，並且先放一個誘餌憑證進去
> 3. **記錄** —— 記下 process、檔案讀寫、對外連線
> 4. **關聯** —— 用 process tree、時間差、同一個使用者把事件串起來
> 5. **判定** —— 放行 / 待審 / 阻擋
>
> 下面這行是分工：**Telemetry 負責證明，規則負責關聯，AI 負責解釋，人負責決定。**」

### 為什麼這樣講

最後那句分工是整個產品的設計哲學，等一下第 10 張會回來呼應。這裡先埋。

---

## 第 4 張 · In practice（怎麼用）

> **開發者實際上要怎麼拿到這個東西**

### 講什麼

> 「三種交付方式，我誠實標了哪些做完了：
>
> **BUILT** —— API 現在就能用。你給我一個 npm 上真實存在的套件名稱，我抓下來、在沙箱引爆、回你一個判定。
>
> **NEXT** —— CLI：你打 `npx traceback install analytics-helper` 取代 `npm install`。
>
> **NEXT** —— MCP server：讓 Cursor 或 Claude Code 在**提議安裝之前**先問過 Traceback。這條最貼合問題本身——真正在裝套件的是 agent，所以應該由 agent 來問。
>
> 還缺的只是把閘門接到日常 `npm install` 前面的那層管線。那是整合工作，不是研究。難的部分已經做完了。」

### 為什麼這樣講

**誠實標示是策略，不是謙虛。** 如果講得像全部做完了，評審問一句「那我現在能用嗎」就破功。先自己講出來，反而顯得有判斷力。

### 可能被問

**Q：MCP 那條要多久？**

> 它是 API 上面的一層轉接，不是新的分析邏輯。引擎已經是 package-agnostic 的。

## 第 5 張 · What you start with（原始資料）

> **六個事件。每一個都是真的。**

### 講什麼

> 「這是沙箱跑完之後拿到的原始 telemetry。六行，每一行都是真的：
>
> npm 起了一個 process、它生了一個子 process、那個子 process 讀了 `.env`、對外連了一個 host、寫了 `deploy.yml`、改了 `.github/workflows`。
>
> **但沒有任何一行告訴你發生了什麼事。**
>
> 這就是今天調查人員實際面對的東西——一堆各自為真、但拼不出故事的紀錄。」

### 為什麼這樣講

先建立「before」狀態，第 8 張的「after」才有對比。Demo 的時候也是這個順序：先按「Run simulation」給他們看原始資料，再按「Build timeline」。

## 第 6 張 · The idea（三層證據）

> **依照主張強度分級**

### 講什麼

> 「這是整個產品的核心想法。每個結論都被標成三種之一：
>
> **FACT** —— telemetry 直接觀察到的
> **CORRELATION** —— 兩個以上觀察，被時間、process tree 或使用者串起來
> **INFERENCE** —— 對意圖的假設，需要人來確認
>
> 而且這是**結構性規則**，不是提示詞裡拜託模型照做：INFERENCE 底下一定要有 CORRELATION，CORRELATION 底下一定要有 FACT。把證據拿掉，結論會跟著消失。這件事有測試在保護。」

### 為什麼這樣講

「這有測試在保護」這句很值錢。它把「我們有規範」變成「規範是可驗證的」。

---

## 第 7 張 · The canary（誘餌）⭐

> **把猜測變成觀察**

### 講什麼

這張是整場最強的一張，慢慢講：

> 「這裡有個難題。『這個秘密到底有沒有被傳出去？』——光看時間差是答不出來的。讀檔案 320 毫秒之後有一個對外連線，看起來很可疑，但你沒有看到封包內容，所以你**不能說**它被傳出去了。
>
> 所以我們在安裝前，先在憑證檔案裡放一個**可辨識的合成 token**——一個誘餌。
>
> 如果這個 token 出現在離開容器的資料裡，那傳輸就不是推測，是**觀察到的事實**。
>
> 於是同一件事，從 INFERENCE 升級成 FACT。
>
> 而且——**當 FACT 出現的時候，系統會把原本那個比較弱的假設收回去**，而不是讓猜測跟證據並排放著。」

### 為什麼這樣講

最後那句是整場最有記憶點的。大部分系統只會往上加結論，不會**撤回**自己的推論。這是「這東西真的在乎正確性」的證明。

### 可能被問

**Q：如果惡意套件把資料加密再傳呢？**

> 那誘餌就不會出現，系統會**退回 INFERENCE**。這是正確的失敗方向——它會少說，不會多說。第 11 張我有寫。

---

## 第 8 張 · The output（判定）

> **BLOCK — high risk**

### 講什麼

> 「這是實際輸出。注意兩件事：
>
> 第一，兩個理由**都標成 FACT**，不是猜測。
>
> 第二，右邊那欄——**Not confirmed**。它老實說它沒能確認的東西：那些 workflow 的修改到底有沒有被 commit、被 push、被執行過。它沒有把這個四捨五入成『已確認』。
>
> 一個藏起自己不確定性的安全工具，比一個沒有不確定性的工具更危險。」

### 為什麼這樣講

指著 **Not confirmed** 那一欄講。這是誠實性的視覺證據，比講一百句「我們很嚴謹」有用。

---

## 第 9 張 · Measured, not illustrated（真實數據）⭐

> **對著真正的 npm registry 跑**

### 講什麼

> 「這些不是示意圖，是實際跑出來的數字。
>
> **esbuild 0.28.1** —— 真的從 npm 抓下來的，它真的有 postinstall hook（`node install.js`），跑出 3 個事件、3 個 FACT、1 個 CORRELATION、0 個 INFERENCE。判定：**放行**。
>
> **lodash** —— 真實套件，完全沒有宣告安裝腳本。答案是『沒有東西可以引爆』。
>
> **最後一行是受控的惡意套件**，我有標 FIXTURE，不會混淆。判定：阻擋。
>
> **第一行才是重點。** 一個什麼都標紅的偵測器毫無價值。一個有真實 postinstall hook 的正常套件，**必須要能通過**——而它通過了。」

### 為什麼這樣講

這張是回答「你這是不是只是 demo」的殺手鐧。**重點放在 esbuild 那行，不是 BLOCK 那行。** 大部分人會炫耀抓到壞人，能證明「不會冤枉好人」才是真的。

### 可能被問

**Q：我可以現場指定一個套件試試嗎？**

> 可以。Demo 頁面上有輸入框，或者直接 curl。（**這題答得出來就贏了，記得先確認 API 有在跑。**）

## 第 10 張 · Why it isn't a model summarising logs

> **模型無法捏造事件**

### 講什麼

> 「為什麼這不是『把 log 丟給 GPT 做摘要』：
>
> **模型從來看不到原始 telemetry。** 它只拿到規則已經推導完的 findings，而且只能用 id 去引用。它回傳的每一個 id 都會跟我們給它的清單對照——對不上的，在寫進資料庫之前就丟掉。它負責排列故事，**它沒有能力增加內容**。
>
> **判定本身是規則算出來的，不是模型。** 一個開發者在決定要不要讓第三方程式碼跑在自己機器上的時候，應該能讀懂那條規則，而且跑兩次要得到一樣的答案。
>
> **機器不會自己確認自己的假設。** 只有人按下 confirm。」

### 為什麼這樣講

這是 AI Security 這個 track 的核心命題：**怎麼讓 AI 的輸出可信**。不是「用 AI 做安全」，是「讓 AI 在安全場景裡可以被信任」。

---

## 第 11 張 · Honest limits（誠實的限制）

> **它無法確立的事**

### 講什麼

主動講，不要等人問：

> 「兩個限制我要主動說：
>
> **第一，telemetry 目前是模擬程式自己回報的**，還沒有從 kernel 抓。真實套件那條路我已經用 `strace` 接了系統呼叫——`execve`、`openat`、`read`、`connect`——但完整替換掉還沒做完。
>
> **第二，誘餌是可以被繞過的。** 套件如果把資料加密再傳，誘餌就不會出現，系統會退回 INFERENCE。它會**少說，不會多說**——這是正確的失敗方向。
>
> 一個藏起自己限制的安全工具，就違背了自己的初衷。」

### 為什麼這樣講

**先講出來的限制不是弱點，是可信度。** 而且你等於預先拆掉了評審手上最尖銳的問題。

---

## 第 12 張 · 結尾

> **Telemetry proves. Rules correlate. AI explains. You decide.**

### 講什麼

> 「Telemetry 負責證明發生了什麼。規則負責把事件關聯起來、算出判定。AI 只負責把已經成立的東西講成人話。**決定權在開發者手上。**
>
> 不要相信套件說它會做什麼——去觀察它實際做了什麼。」

停住。不要再補充。

## Demo 順序（如果要現場操作）

配合投影片，建議在第 5 張跟第 8 張之間切到 demo：

1. 開 <http://localhost:5173/traceback>
2. 按 **Run simulation** → 指著原始事件表：「這是六行 telemetry，每行都真，沒有一行解釋任何事」
3. 按 **Build timeline** → **大約 9 秒**，這段時間講：「它在關聯事件，模型在寫時間軸——但模型看不到原始 telemetry，它只能排列規則已經推導出來的東西」
4. BLOCKED 卡片出現 → 講第 8 張的內容
5. 捲到某個 INFERENCE，指著 **Confirm finding** 按鈕：「機器不會自己按這個」

**現場輸入真實套件**（如果時間夠，這招最強）：
在 inspect 輸入框打 `esbuild` → 等結果 → **ALLOW**。

> 「一個真實的、有 postinstall hook 的正常套件，它放行了。」

## 如果出事了

| 狀況                                  | 怎麼講                                                                                                                                |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| 出現橘色 banner 說用了 local fallback | **講出來**：「Modal 連不上，所以它退回本地資料，而且**標示出來了**。fallback 永遠不會被當成真的沙箱結果呈現。」這個誠實本身就是產品。 |
| 時間軸顯示 generated by rule-engine   | 「沒有 API key，所以是決定性引擎寫的——系統的正確性不依賴模型。」                                                                      |
| Build timeline 超過 20 秒             | 繼續講第 10 張的內容，講完剛好回來。                                                                                                  |
| 完全掛掉                              | 開另一個分頁——之前跑完的調查都存在 Supabase 裡，重新載入就有。                                                                        |

**上台前一定要做**：先完整跑一次，那個分頁**不要關**，放在背景當保險。

## 一分鐘濃縮版

如果時間被砍到 60 秒：

> 「AI coding agent 會問你能不能跑 `npm install`。但 npm 會自動執行套件作者寫的安裝腳本——那段程式碼可以讀你的 `.env`、對外連線、改你的部署設定。**這些都不在你批准的那個對話框裡。**
>
> Traceback 先在隔離沙箱裡把那段腳本跑一遍，看它實際做了什麼，然後給你放行、待審、或阻擋。
>
> 每個結論都標成 FACT、CORRELATION 或 INFERENCE，而且都連回原始事件。模型看不到原始資料，所以它沒辦法捏造；判定是規則算的，不是模型猜的；INFERENCE 一定要人來確認。
>
> 而且它對 npm 上真實的套件跑得起來——esbuild 有真的 postinstall hook，它放行；惡意套件，它阻擋。**能證明不冤枉好人，比能抓到壞人更重要。**
>
> Telemetry 負責證明，規則負責關聯，AI 負責解釋，人負責決定。」
